# Dotfiles

Personal macOS and Ubuntu/Debian development setup, managed with chezmoi.
This repository owns portable shell/Git/editor settings and shared personal
agent defaults and skills. Credentials, sessions, provider settings, and
project-owned skills remain outside this public repository.

- `install.sh` installs chezmoi, applies dotfiles, and runs the OS bootstrap.
- `mise.toml`, `mise.lock`, and `.mise/locks/` own shared tools; generate locks
  with the pinned mise release, never by hand. `mise-bootstrap.env` pins mise.
  Read `docs/tools.md` for sandbox setup, updates, and verification.
- `Brewfile.macos` and `packages/ubuntu.sh` own system package lists; shared
  runtimes are installed through the portable tools entrypoint.
- `agents/AGENTS.md` and `agents/personal-skills/` own tracked guidance and
  custom skill sources.
- `skills-lock.json` owns pinned upstream/custom selections. The pinned Skills
  CLI restores ignored `agents/runtime/`; chezmoi owns only discovery links.
  Read `docs/agents.md` before catalog changes; run `bash scripts/test-skills.sh`.
- `.chezmoiignore` excludes repository-only files and platform-specific targets.
- Keep README focused on setup, update, and edit; put details in `docs/setup.md`.
- Run `bash scripts/check.sh`, adding `test-chezmoi.sh` for deployment or
  template changes and `test-scripts.sh` for script changes. Tests deploy into
  disposable destinations; never apply the full configuration to the developer's
  home. Container commands and coverage limits live in `docs/setup.md`.
- Whenever you change this repository, run the relevant checks, commit your
  changes, and push to the remote before finishing the task. Include only the
  task's changes in the commit and preserve unrelated local edits.

## Where to look

| Need | Location |
| --- | --- |
| Shared tool pins | `mise.toml`, `mise.lock`, `.mise/locks/`; `mise-bootstrap.env` pins mise itself |
| Skills catalog (upstream selections, pins, hashes) | `skills-lock.json`; restored by `scripts/install-skills.sh` into ignored `agents/runtime/` |
| Custom skill sources | `agents/personal-skills/` |
| Agent behavior defaults | `agents/AGENTS.md`, deployed to `~/.agents/AGENTS.md` |
| Agent model, roster, and skills ownership | `docs/agents.md` |
| System package lists | `Brewfile.macos`, `packages/ubuntu.sh` |
| Bootstrap, update, and check scripts | `scripts/` (`bootstrap-*`, `update-*`, `check.sh`, `test-*.sh`) |
| Setup and tooling documentation | `docs/setup.md`, `docs/tools.md` |
| Git identity and signing template | `dot_gitconfig.tmpl` (chezmoi data: `git_name`, `git_email`, optional `git_signing_key`) |

## Standing rules

- The skills catalog follows upstream membership: removals propagate, and
  splits or renames adopt the successor skill(s). Nothing stays frozen at an
  old pin by choice.
- Lock pins (`skills-lock.json`, `mise.lock`) are integrity snapshots
  refreshed to upstream HEAD, not divergence. Regenerate them with the
  pinned tools; never edit pins or hashes by hand.
- The Skills CLI stays pinned at 1.7.4 until the repo verifier supports the
  v2 lock format; CLI 1.8.1 rewrites the v1-format lock during restore.
- Run `bash scripts/check.sh`, plus the suite for the area touched, before
  pushing; commit and push before finishing the task.
- dev-workbench consumes this repository as a pinned submodule. Pin bumps
  are Renovate's job and land as reviewed updates, never hand edits.

## Anti-patterns

- Editing `agents/runtime/`: it is generated by the pinned Skills CLI
  restore, so edits are overwritten and fail verification.
- Copying skill files into the runtime tree instead of changing the
  catalog through `skills-lock.json` and the `docs/agents.md` flow.
- Applying the full configuration to your real home to test; tests deploy
  into disposable destinations.
- Committing credentials, sessions, or provider settings; this repository
  is public, and secrets belong in chezmoi private config or 1Password.

## Agent goals

Goal behavior is owned by `agents/AGENTS.md`, deployed to `~/.agents/AGENTS.md`
and inherited by Codex, Claude Code, Muse Code, and OpenCode. That file decides
when to set a goal and what closing one requires.

For dotfiles work, a goal names its proof: `bash scripts/check.sh` and the
suite for the area touched pass, the task's files are clean in `git status`,
and the commit is pushed.
